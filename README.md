# Time4Med — Smart Medicine Cabinet

Time4Med เป็นโครงการตู้ยาอัจฉริยะสำหรับผู้สูงอายุ โดยให้ผู้ดูแลจัดการตารางยาผ่านเว็บไซต์และติดตามข้อมูลที่ระบบบันทึกไว้

## ระบบปัจจุบัน (3 พฤศจิกายน 2026)

- เว็บไซต์หลัก: [Time4Med GitHub Pages](https://n4-p4t.github.io/Time4Med/) → `test-v021/`
- Frontend: `test-v021/index.html`, `test-v021/gas-only.js`, `test-v021/gas-only.css`
- Backend: Google Apps Script (ต้นฉบับใน `apps-script/Code.gs`)
- ข้อมูล: Google Sheets (รวมถึง `MealMedicines`, `Users`, `Devices`, `ActivityLog`)
- รูปภาพหลักฐาน: Google Drive เมื่อ ESP32-CAM ส่งข้อมูลเข้าระบบได้
- แจ้งเตือน: LINE ผ่าน Apps Script เมื่อกำหนดค่าและเปิดใช้งานที่ backend
- อุปกรณ์: ESP32-S3 (ระบบควบคุมตู้), ESP32-CAM (กล้อง)

**ไม่มี Cloudflare Worker หรือ HiveMQ/MQTT ในสถาปัตยกรรมปัจจุบัน** และไม่ควรนำโค้ดระบบเก่ากลับมาใช้โดยไม่วิเคราะห์ผลกระทบ

## ผู้ใช้งานและชั้นยา

- `ADMIN`: จัดการระบบและบัญชีผู้ดูแล
- `CAREGIVER`: เห็นและจัดการยาของผู้สูงอายุที่ตนได้รับสิทธิ์เท่านั้น
- ชั้น 1: P001, ชั้น 2: P002, ชั้น 3: P003 — แต่ละชั้นมี LED 4 ดวง (เช้า/กลางวัน/เย็น/ก่อนนอน)
- ชั้น 4: ยาสามัญประจำบ้าน ไม่มี LED เฉพาะบุคคล

Backend ต้องตรวจสิทธิ์ผู้ใช้งานทุกครั้ง ไม่ใช้เพียงการซ่อนปุ่มบนหน้าเว็บเป็นมาตรการรักษาความปลอดภัย

## ตารางยา

หน้าเว็บเพิ่ม แก้ไข และปิดใช้งานรายการยาได้ผ่าน Apps Script และ Google Sheets รายการที่มีชื่อหรือรหัสขึ้นต้น `TEST_`, `DEMO_`, `LINECHECK_` เป็นข้อมูลทดสอบที่ **ไม่ส่งเป็นตารางยาจริงไปยัง ESP32-S3 หรือ LINE** ตามการกรองของ backend

Heartbeat บอกเพียงว่าตู้ติดต่อ server เมื่อใด **ไม่ใช่หลักฐานว่าซิงก์ตารางยาล่าสุดสำเร็จ** หรือว่าผู้สูงอายุรับประทานยาแล้ว หน้าเว็บไม่ควรแสดงคำว่า SYNC สำเร็จโดยไม่มีการยืนยันจากอุปกรณ์

## ข้อจำกัดที่ยังต้องทดสอบ/ดำเนินการ

1. การซิงก์รายการยาจาก Sheets → ESP32-S3 ครบวงจร รวมการปิดรายการและตารางว่าง
2. ยาที่ต้องแจ้งเตือนทุก 8 ชั่วโมง **นับจากเวลายืนยันครั้งแรกจริง** ต้องมี backend และเฟิร์มแวร์รองรับ ไม่ใช่เพิ่มสามเวลาคงที่แทน
3. ภาพจาก ESP32-CAM → Google Drive → หน้าแกลเลอรี และการทดสอบกับตู้จริง
4. ปุ่มสาธิตสำหรับ ADMIN ต้องมี Apps Script deployment ที่รองรับและ ESP32-S3 ที่ส่ง `demoPoll/demoEvent` ก่อนจึงจะยืนยันว่าใช้งานได้
5. การเปิดใช้งาน LINE ตามเวลาและนโยบายเก็บรูปต้องตรวจ Script Properties และ Triggers ที่ deploy อยู่ก่อน ไม่ถือว่าพร้อมเพียงเพราะมีโค้ด

- ห้ามใส่ token, รหัสผ่าน, DEVICE_API_KEY หรือ LINE Channel Access Token ใน GitHub Pages หรือ repository
- เปลี่ยนเฉพาะสิ่งที่จำเป็นและตรวจสอบผลก่อนถือว่าเสร็จจริง
