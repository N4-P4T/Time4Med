# Time4Med v0.24 — เชื่อม ESP32-S3 กับเว็บไซต์เพื่ออ่านสถานะสด (READ ONLY)

## ทำอะไรได้แล้ว
- เว็บ Caregiver Center v0.21 เพิ่มกล่องสถานะ HiveMQ ที่แสดงประตู/กลอน/ฉุกเฉิน เมื่อได้รับ MQTT status ใหม่จริงจาก ESP32-S3 หลังจากเชื่อม
- ต้องเข้าสู่ระบบ Google ก่อนจึงเปิดกล่องได้
- ผู้ดูแลใช้บัญชี HiveMQ ที่จำกัด ACL แบบ **SUBSCRIBE ONLY** (เฉพาะ \`time4med/v1/cabinet/cabinet-01/status\`) เท่านั้น
- ผู้ใช้กรอกรหัสผ่านเองต่อแท็บ ไม่บันทึกลง GitHub, localStorage หรือ sessionStorage; ข้อมูลฟอร์มล้างเมื่อเริ่มเชื่อม
- ใช้ WSS/TLS ผ่าน port 8884; ไม่ publish/ไม่สั่งกลอน/ไม่แก้ตารางยา
- ไม่เชื่อ retained MQTT message (สถานะเก่าที่ Broker ค้างไว้)
- หากไม่มีสถานะใหม่ภายใน 150 วินาทีให้แสดงขาดข้อมูลสด ไม่แสดงออนไลน์จาก stale retained value
- เมื่อออกจากระบบ Google ตัดการเชื่อมต่อและล้างสถานะบนหน้าจอ

## ขั้นตอนฝั่งผู้ใช้ (สำคัญ)
1. ที่ HiveMQ Cloud → Access Management → สร้างบัญชีชื่อใหม่ เช่น \`time4med-viewer\` และรหัสแบบสุ่ม (อย่าใส่ใน GitHub)
2. ใช้ ACL จำกัด Subscribe ได้เพียง Topic \`time4med/v1/cabinet/cabinet-01/status\` ห้าม Publish ไปยัง Topic ใด ๆ รวมถึง command/lock และ command/schedule
3. อย่าใช้รหัส \`time4med-esp32s\` ของเครื่องในหน้าเว็บนี้ และ **เปลี่ยนรหัสที่เคยเผยแพร่สาธารณะ**
4. เปิดหน้าเว็บ, Google Login → Dashboard → กล่อง \`เชื่อมสถานะสด ESP32-S3\` → ใส่บัญชี Viewer
5. เปิด ESP32-S3 ที่รันเฟิร์มแวร์เดิมซึ่งส่ง topic status; ต้อง Wi-Fi และ HiveMQ เชื่อมสำเร็จ
6. รอรอบ Status MQTT ถัดไป (ปกติ 60 วินาที). ก่อนเห็นข้อมูลใหม่จะขึ้นข้อความว่า Broker เชื่อมแล้วแต่ยังไม่ทราบว่าอุปกรณ์ออนไลน์
7. ถ้าใช้งานไม่ได้ ส่งข้อความจาก Console/Serial **เฉพาะสถานะทั่วไป ห้ามส่ง password, token, secrets.h หรือบัญชี HiveMQ**

## สิ่งที่ยังไม่สำเร็จ
- **ยังไม่ได้ทดสอบ MQTT กับ ESP32-S3 จริง** เพราะไม่มีสิทธิ์เข้าถึงเครื่อง/บัญชี HiveMQ จากเครื่องมือของผู้ช่วย
- หน้า Monitor เป็นทางเลือกสำหรับผู้ดูแลที่ผ่าน Google Login แต่บัญชี HiveMQ ยังจำเป็นต้องมี ACL แบบ read-only; แม้ JS ไม่ publish บัญชีที่มีสิทธิ์ publish ก็ยังเสี่ยงถูกใช้จาก Developer Tools
- การส่งตารางยาจาก Google Sheets → Cloudflare Worker → ESP32-S3 พร้อม ACK ยังไม่เปิดใช้งานจริง: ดู PR #13 staging ซึ่งต้องมี Gateway สำหรับส่งคำสั่ง HMAC/nonce และ firmware สาย MQTT v2
- สถานะกลอน/ประตูที่แสดงมาจาก telemetry; ต้องเทียบกับฮาร์ดแวร์ก่อนใช้ตัดสินใจดูแลผู้สูงอายุ

## สำหรับเล่ม
รูปการเชื่อมต่อหลังได้รับข้อมูลสดจาก ESP32-S3 สามารถแนบเป็นผลทดลองได้ เมื่อทดสอบผ่านจริงแล้ว โปรดอย่าใช้ข้อมูลที่จำลองใน GitHub Actions เป็นหลักฐานการทดสอบฮาร์ดแวร์
