# Time4Med — ระยะที่ 4: ตรวจสิทธิ์และมื้อยาที่ถึงกำหนด (ยังไม่ส่งอัตโนมัติ)

หลังจากการทดสอบจริง **Google Sheets → Google Apps Script → LINE** ผ่านและมีภาพแชต LINE ยืนยันแล้ว ขั้นต่อไปคือเตรียมกติกาที่ปลอดภัยก่อนให้การแจ้งเตือนทำงานเอง

## ทดสอบเบื้องต้นผ่าน Google Apps Script

1. เปิดโปรเจกต์เดิม `Time4Med_LINE_Pilot` ที่มี `Code.gs`, `SheetPreview.gs` และ `SheetLineDemo.gs`
2. กด **+ → Script** เพิ่มไฟล์ชื่อ `ReminderPreview`
3. คัดลอกโค้ดทั้งหมดจาก [ReminderPreview.gs](./ReminderPreview.gs) วางแล้ว Save
4. ใช้ Script Property `TIME4MED_SHEET_ID` **ค่าเดิม** ไม่ต้องตั้งใหม่
5. เลือกฟังก์ชัน **`previewTime4MedReminderPlan`** → **Run**
6. อ่านผลใน Execution log: `mode:"PREVIEW_ONLY_NO_NOTIFICATIONS"` และ `wouldSendNow:false` ต้องเป็นเช่นนี้เสมอในระยะนี้

ฟังก์ชันนี้ใช้เขตเวลา `Asia/Bangkok`, อ่าน **MealMedicines** (header แถว 1) และ **Users** (header แถว 4); ไม่ส่ง LINE ไม่เปลี่ยน Sheets ไม่ตั้ง Trigger หรือ Webhook ไม่แก้เว็บไซต์และไม่เกี่ยวกับ Cloudflare

## เกณฑ์คัดกรอง

### ตารางยา
- เฉพาะ `is_active=TRUE`
- คัดแถวชื่อทดสอบ/ตัวอย่าง (`TEST_*`, `DEMO`, `ทดสอบ` ฯลฯ)
- `kind=scheduled`, `patient_id` เป็น `P001,P002,P003`, หมายเลข `box_number` ต้องตรงกับช่องยา 1/2/3
- `meal_type` เป็นเลข `1–7`; `reminder_time` ต้องเป็น `HH:mm`
- ยาหลายรายการของผู้สูงอายุคนเดียวกัน ในมื้อ/เวลาเดียวกันจะถูกรวมเป็น **เหตุการณ์มื้อเดียว** เพื่อเตรียมลดการส่งซ้ำ

### ผู้รับ
- เฉพาะ `ADMIN` หรือ `CAREGIVER`, `status=ACTIVE`, `notification_enabled=TRUE`, LINE User ID มีรูปแบบถูกต้อง
- ADMIN ที่มี `patient_id=ALL` ดูได้ทุกคน
- CAREGIVER ต้องมีรายการรหัสผู้สูงอายุที่ได้รับสิทธิ์ เช่น `P001,P002`; ค่า ALL ของ CAREGIVER จะถูกปฏิเสธ
- หาก LINE User ID เดียวกันปรากฏหลายแถว จะนับเป็นผู้รับคนเดียว และคิดขอบเขตของบัญชีนั้นรวมกัน
- ผลแสดง **เฉพาะจำนวนผู้รับ** ไม่แสดง LINE User ID, ชื่อยา, ชื่อผู้สูงอายุ หรืออีเมลใน Log

## ทำไมยังไม่เปิดส่งอัตโนมัติ

ณ เวลาตรวจ 2026-10-27 รายการที่ Active 2 รายการยังเป็น `TEST_P001` และ `TEST_P002` ดังนั้นจำนวนมื้อยาจริงที่พร้อมส่ง = 0

และ `MealMedicines` ที่มีอยู่บันทึก **เวลา** แต่ไม่มี `days_of_week` ในแถว: ห้ามอนุมานว่ายาทุกตัวต้องรับประทานทุกวันโดยไม่ยืนยันความต้องการจริง นอกจากนี้ยังขาดการตรวจจับคู่ผู้รับตามบุคคลครบวงจร, การบันทึก ledger ป้องกันส่งซ้ำ, เกณฑ์ปรับการเตือน, และการจัดการโควตาตามจริง

**การตรวจว่ามีมื้อถึงกำหนดในเวลาปัจจุบันเป็นเพียงการเทียบ HH:mm ไม่ใช่คำสั่งให้ส่ง**; `wouldSendNow` ยัง `false` โดยออกแบบไว้

## ก่อนทำระยะส่งอัตโนมัติจริง

- บันทึก/ยืนยันรายการยาจริง พร้อมเวลารับประทานและวันที่ต้องแจ้ง
- ยืนยัน LINE ID ผู้ดูแลแต่ละคนและขอบเขต P001–P003
- กำหนดระบบ ledger/idempotency และการจัดการผลลัพธ์ error
- ทดสอบด้วยข้อมูลจำลองก่อนเปิด Trigger และใช้ข้อความที่ไม่เปิดเผยข้อมูลสุขภาพ
