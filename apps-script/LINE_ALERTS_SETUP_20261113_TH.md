# Time4Med — เตรียม LINE-only ก่อนทดสอบตู้จริง 14 พฤศจิกายน 2569

## สถานะ (13 พ.ย. 2569)
- ปัจจุบัน GAS เดิมส่ง LINE ถึงเวลามื้อยาได้ และ NotificationLog บันทึก SENT ในวันที่ 12 พ.ย. ครบ P001, P002, P003
- ไฟล์เสริม `Time4Med_LINE_Alerts_20261113.gs` ใหม่ ไม่ได้แตะเว็บไซต์ที่กำลังทำงาน ไม่แก้ OTP ไม่เปลี่ยน GAS /exec ไม่เปลี่ยนรหัส Device หรือ LINE
- เพิ่ม LINE เมื่อบันทึกการกดยืนยันรับยา, แจ้งไม่พบยืนยันหลังถึงเวลายา 2 นาที (เมื่อมีประวัติ LINE ถึงเวลายาที่ส่งสำเร็จ), แจ้ง S3/CAM ขาดการติดต่อเกิน 5 นาทีแบบไม่ส่งซ้ำ, และเปิด/ปิดประตู **เฉพาะเมื่อ** `ActivityLog` มี DOOR_OPEN/DOOR_CLOSED จาก S3 จริง
- ข้อความกดยืนยันหมายถึง "กดปุ่มแล้ว" ไม่ใช่ยืนยันว่ากลืนยา
- ตรวจค่า `Settings!LINE_MONTHLY_SOFT_LIMIT` (ปัจจุบัน 250) สำหรับ **ข้อความใหม่ที่ส่งผ่านไฟล์เสริม**; จำนวนที่บันทึกใน NotificationLog อาจไม่เท่ากับยอดทางการ LINE OA Manager
- **สำคัญ:** ตัวส่ง LINE ถึงเวลายาเดิม (`scheduledLineReminders_`) ยังไม่ได้ใช้ soft limit ใหม่นี้ร่วมกัน ต้องแก้เพิ่มก่อนนำไปใช้งานหนักในระยะยาว

## ลงไฟล์เสริมใน GAS ที่ใช้งานจริง (ทำได้จากห้อง ไม่ต้องเปิดตู้)

1. เปิด [Google Apps Script](https://script.google.com/home/projects) ด้วยบัญชีที่เป็นเจ้าของ Time4Med (**time4med.project@gmail.com**) แล้วเปิดโครงการที่ URL /exec ของ Time4Med ใช้งานอยู่
2. ไปที่ **Files > + > Script** ตั้งชื่อ `Time4Med_LINE_Alerts_20261113`
3. คัดลอกเนื้อหาไฟล์ [Time4Med_LINE_Alerts_20261113.gs](./Time4Med_LINE_Alerts_20261113.gs) **ทั้งหมด** วางในไฟล์ใหม่ ห้ามลบหรือแทนที่ `Code.gs` / `doPost` / `doGet` เดิม
4. กด **Save** แล้วเลือกฟังก์ชัน `time4medLineAlertsCheck` และ **Run** เพื่อดูว่า `hasToken:true`, `destinations > 0` และ `softLimit:250`
5. เลือก `time4medLineAlertsTestOnce` แล้ว Run ครั้งเดียว → จะส่งข้อความขึ้นต้น **[Time4Med TEST]** ไปยัง LINE ผู้ดูแล ADMIN หนึ่งปลายทางเท่านั้น ไม่มีข้อมูลผู้ป่วยหรือเหตุฉุกเฉินปลอม (ระบบเว้นการทดสอบซ้ำ 10 นาที)
6. หาก LINE ได้รับพร้อมแบนเนอร์และเสียง ให้เลือก `time4medLineAlertsStart` แล้ว Run ครั้งเดียว เพื่อติดตั้ง Trigger ทุก 1 นาที โดยตั้งจุดเริ่มต้นใหม่และไม่แจ้งย้อนหลังสำหรับเหตุการณ์ก่อนเริ่ม
7. ตรวจ `time4medLineAlertsCheck` อีกครั้งให้แสดง `enabled:true` และ `triggerCount:1`

**ไม่จำเป็นต้อง Deploy Web App ใหม่** สำหรับไฟล์เสริมที่อ่านข้อมูลจาก Google Sheets ด้วย Trigger โดยตรง แต่ **ต้อง Deploy ใหม่** หากไปแก้ `postDevice_` ให้รับ action `door` ใน Web App

หากต้องหยุดระบบเสริม เรียก `time4medLineAlertsStop` เพียงครั้งเดียว การแจ้งเตือนมื้อยาเดิมไม่ถูกลบ

## ประตูตู้ยา: ต้องบันทึกการเปลี่ยนสถานะจาก S3 จึงจะส่ง LINE ได้

ระบบที่ใช้อยู่ปัจจุบันยังไม่ส่ง action `door` จาก S3 ใน protocol ที่ยืนยันได้ จึง **ยังไม่สามารถรับรองการแจ้งเปิด/ปิดประตูจริง** จนกว่าจะลงเฟิร์มแวร์และ Web App ด้วยกัน

ใน `Code.gs` ที่ใช้งานอยู่ หา `postDevice_`:
- หลังตรวจ `deviceAuthenticated_(p.deviceKey)` ให้เพิ่ม `'door'` ใน action whitelist
- เพิ่ม `if(p.action==='door') return time4medDoorChangeFromDevice_(p);` ก่อนเข้าโค้ดอ่าน patientId/heartbeat
- จากนั้น **Deploy > Manage deployments > Edit > New version > Deploy** ใช้ /exec **URL เดิม**

ใน firmware ESP32-S3 ตัวที่ใช้งานจริง ให้ใช้ HTTPS POST **โครงสร้างเดิม/DEVICE_API_KEY เดิม** เมื่อ Reed Switch เปลี่ยนสถานะเท่านั้น:
```json
{"action":"door","deviceId":"S3-001","door":"OPEN","deviceKey":"<secret-from-device-settings>"}
```
หรือ door = CLOSED; **ห้ามนำ secret จริงไปใส่ GitHub หรือบันทึกภาพหน้าจอ**
- ครั้งแรกที่รับสถานะประตูจะเก็บเป็นค่าเริ่มต้นโดยไม่ส่งแจ้งเตือน (กันการเปิดเครื่องแล้วแจ้งผิด)
- การเปลี่ยน OPEN ↔ CLOSED ที่ตามมาจะบันทึก `ActivityLog` และไฟล์เสริมส่ง LINE หนึ่งครั้งต่อเหตุการณ์
- ต้องใช้โค้ด ESP32-S3 ฉบับที่อัปโหลดอยู่บนบอร์ดจริงจึงจะต่อฮุกได้ปลอดภัย ห้ามเปลี่ยนขา GPIO กลอน/ไฟ/เสียงโดยเดาสุ่ม

## จุดทดสอบวันเสาร์ที่ 14 พ.ย. 2569

1. ตรวจว่าโทรศัพท์ผู้ดูแลได้รับข้อความ [Time4Med TEST] และ LINE เปิดเสียงแจ้งเตือนแล้ว
2. ตรวจ Dashboard + Devices S3-001 และ CAM-001 ออนไลน์
3. **รายการสาธิต 12 พ.ย. ทั้ง 3 ชั้นตั้งวัน `THU` ไม่ใช่ `SAT`** — ต้องตั้งวัน/เวลาให้ตรงกับการทดสอบวันเสาร์ก่อนเริ่ม แล้วรอ S3 ยืนยัน schedule ACK ใหม่ ห้ามเข้าใจว่าไม่มีเตือนเพราะ LINE เสีย
4. ทดสอบถึงเวลายา → LINE; กดยืนยัน → LINE ภายหลังระบบบันทึก IntakeLog (ไม่ใช่หลักฐานกลืนยา)
5. ทดสอบไม่กดยืนยันหลัง 2 นาทีหนึ่งรอบ และตรวจว่าไม่มีข้อความซ้ำ
6. ทดสอบเปิด–ปิดประตู **หลัง** อัปเดต GAS + S3 แล้วเท่านั้น
7. เก็บหลักฐานเวลาใน LINE และ NotificationLog สำหรับบทที่ 4 รวมทั้งข้อจำกัด (LINE ส่งสำเร็จไม่เท่ากับอ่านแล้ว)

## สิ่งที่ยังไม่เสร็จ ณ เวลาสร้างไฟล์

- ไฟล์เสริมถูกจัดทำใน GitHub แต่ **ยังไม่ถูกติดตั้ง/Run ในโครงการ Apps Script จริง**
- ยังไม่มีการแก้หรืออัปโหลดเฟิร์มแวร์ ESP32-S3 เพื่อให้รายงานเหตุการณ์ประตู
- ยังไม่ทราบว่า GAS `Code.gs` ใน Editor ฉบับใช้งานจริงตรงกับฉบับ GitHub หรือไม่ จึงห้ามคัดลอกไฟล์ Code.gs เก่าทับ
- ยังไม่ได้ตรวจยอด LINE 300 ข้อความของบัญชีใน LINE OA Manager (นับตามผู้รับ/เดือน)
- ปุ่มฉุกเฉินถูกถอดออกแล้ว: ไม่ควรอ้างว่าปุ่มฉุกเฉินยังทำงาน; ต้องจัดการสัญญาณ GPIO ให้ไม่ลอยในเฟิร์มแวร์ที่ใช้อยู่

**หลักการ:** ทดสอบจากสถานะจริง ลดการส่งซ้ำ ไม่แตะโครงสร้างที่ใช้งานได้ ไม่ทำ Web App /exec เปลี่ยน URL
